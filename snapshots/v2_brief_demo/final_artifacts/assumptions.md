# 假设清单（决策引用的 id）

| id | 假设 | 默认 |
|---|---|---|
| A1 | 第一版是单人使用、以对话/快速输入为主的轻量产品（手机优先），不做多人协作；主要用户是自主时间多的学生和自由职业者（人类回答；该回答标注为演示代答，建议后续用真实用户核实）。 | 单人、手机优先、文本（可语音转文字）输入；主要用户为学生与自由职业者，上班族为次要验证对象 |
| A2 | 用户不愿意逐条填写时长、优先级等结构化字段；输入以自然语言"倾倒"为主，系统负责补全并让用户可快速纠正。 | 自然语言一次性输入，助手给出默认估时与优先级推断，用户可一键修改 |
| A3 | 固定事项在目标用户的一天里较少（课程、预约、客户会、接送等），可口述；用户已有日历，但首版不必依赖它。日历导入降为可选，不写回、不替代日历。 | 口述固定事项为主；可选只读导入当天日历（可后置到首版之后）；不写回 |
| A4 | "想做但不一定要做"的事是软任务：只填充真实空档，在时间紧张时第一个被舍弃，且舍弃要被明确告知而不是静默消失；舍弃时可提供缩小版本。 | 三类任务：固定（预约/会议/课程）/必做/可选；可选永远不挤压前两类 |
| A5 | 重排由用户主动触发（一句话告知变化）；助手不在后台持续监测，只在用户设定的少数节点（如下一个固定事项前）轻提醒。 | 用户触发重排 + 仅在固定事项前提醒，默认不推送其他通知 |
| A6 | 估时过于乐观和拖延是计划不靠谱的最大来源，对自主时间多的用户尤其如此。第一版靠保守默认值、缓冲时间和用户当天修正来应对，不依赖历史学习。 | 默认给任务加缓冲（约 20–25%，自主任务高于固定事项），标出估时置信度低的任务；午间可做一次"进度校准" |
| A7 | 自主时间多的用户的核心难点是：没有外部结构，需要助手帮忙决定顺序、整块专注时间的位置、休息与软任务的位置，并围绕硬截止（交付、考试、论文）倒推可行性。 | 排程重点放在专注块安排、截止倒推与软任务保留，而不是避让大量会议 |
