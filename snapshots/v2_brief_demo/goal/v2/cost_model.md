## 功能成本估算（S=1，M=3，L=8 点）
以"一个小团队在已有 LLM 能力上交付的工作量与风险"来估，兼顾工程量、不确定性（尤其是排程可靠性）和对隐私/授权的负担。主要用户是自主时间多的学生/自由职业者，因此预算向"专注块安排、截止倒推、拖延后的重排"倾斜，而不是会议缝隙优化。

- **S（1 点）**：单一界面或规则、无外部依赖、行为可由确定性逻辑验证。
  - 例：任务三分类标签（固定/必做/可选）；晚间未完成清单勾选；"从现在重新开始"的入口按钮；固定事项前一次性提醒；任务可选截止日期字段。
- **M（3 点）**：需要一定的排程逻辑或 LLM 解析，有明显的边界情形，但不依赖外部系统。
  - 例：自然语言倾倒 → 结构化任务解析（含默认估时与缓冲）；整块专注时间与截止倒推的排程；最小改动重排并生成差异说明；午间进度校准（基于已完成情况重估剩余时间）；冲突/缺失信息的暴露与确认流程；跨午夜的"自定义一天"。
- **L（8 点）**：外部集成、授权/隐私合规、后台逻辑，或需要大量数据才能做好。
  - 例：日历双向同步（及完整的日历只读导入授权流程，目标用户固定事项少，默认推迟）；后台监测与主动推送；基于历史的估时学习；多人会议协调。

### 使用规则
1. 每个功能须标注点数及其依据；L 级功能进入首版必须有对应场景的强理由，否则默认推迟（日历导入在新的目标用户下默认推迟）。
2. 首版总预算建议控制在约 **15–20 点**，且至少 70% 的点数用于"排程 + 重排"核心闭环。
3. 不确定性高的项（如重排质量、估时校准）估算上浮一档，并写出验证方式（用上述场景，尤其 S3、S11、S12 做人工评审）。
4. 与核心闭环无关的 S 级功能累计也不应超过 3 个，以避免功能堆积。
