# P001 — shared memory: single source, capped team taste, rating comments reach the team

category: learning · branch: meta/P001 · base: evolve/main 04d84ba

## What changed
1. **Single source of truth** (`src/sea/executor.py`, `_Run.reads_shared`, `SHARED_KEY = "human_answers"`):
   in v2 `run_llm`, the system-message block "What the team has learned from the human so far" (memory/_shared.md)
   is skipped for a role that already places the live context key `human_answers` (in `reads` or as `{human_answers}`
   in its prompt), and only when the episode context actually has that key. Every other llm role still gets the block.
   The v1/legacy path is untouched.
2. **Distilled, capped team taste** (`src/sea/tasks/brief/task.py`, `BriefTask.shared_notes`): the text written to
   memory/_shared.md and given as `human_answers` is now: newest ≤4 rating comments + newest answers, ≤12 bullets in
   total, each bullet ≤200 chars, whole text ≤1200 chars (oldest answers dropped first, then oldest comments).
   Answer bullets keep the old format `- question -> answer`. Deterministic formatting, no LLM — it only changes when
   the human says something new, so evaluations are stable.
3. **Rating comments reach the team**: `python -m sea.human rate <genome> <score> "<comment>"` comments are now
   bullets `- rating of design <id>: <score>/5 — <comment>` in the taste (bare scores without a comment are skipped).
   Previously they reached only the Framer (refresh) and the evolver workspace (human.md).
4. Docs: `DESC` context-selector line in brief task.py and the genome.py docstring describe the new semantics.
5. Test: `src/sea/brief_test.py::test_shared_taste_single_source_with_comments_and_cap` (no duplication for a role
   reading `{human_answers}`, system-block fallback for a role that does not, comments visible, cap, determinism).

## Why (evidence)
- Proposal evidence 1: `genomes/v2/brief_P0` reads `{human_answers}` and also got `_shared.md` in its system message.
  Reproduced with `meta/bench/genomes/brief_P0_shared` in the tier-B trace driver (fake LLM, run locally, no paid
  calls): the human answer appeared **2×** in the single prompt on base, **1×** on this branch.
- Evidence 2: `shared_notes()` was an uncapped list → now capped.
- Evidence 3: no role ever saw rating comments → now every llm role does (via the key or the system block).

Decision on direction: keep the **context key** and drop the system copy for roles that read it, because (a) the key is
live (computed from the inbox each run) while `_shared.md` is a snapshot from the generation start, (b) genomes that
place `{human_answers}` explicitly chose where it goes in their prompt, and dropping the key would break them, and
(c) the executor stays generic: benchmark tasks have no `human_answers` key, so nothing changes for them.

## Expected effect on prompts / tokens (local tier-B trace, fake LLM)
| trace | base chars | P001 chars |
|---|---|---|
| calendar P0/S0 × 5 episodes (15 traces incl. brief) | — | **identical** |
| genomes/v2/brief_P0 | 2416 | 2416 (no `_shared.md` in the genome dir in the trace) |
| meta/bench/genomes/brief_P0_shared | 2521 | **2416** (answer 2× → 1×) |
| demo_g1_c1..c3 | unchanged | unchanged (each call contains the answer at most once) |

In real brief runs every role that reads `{human_answers}` saves one copy of the taste per call (≤1200 chars once
capped), and the taste itself no longer grows without bound. Rating comments add ≤4 short bullets.

## Risks
- Behaviour change in brief runs: roles now see rating comments ("too many features"), which can shift designs; this
  is the intended effect but C-tier fitness may move.
- Old answers beyond the cap leave the team prompt (they stay in the inbox, human.md and the Framer's goal versions).
  With ≤12 answers in practice so far this does not trigger.
- A role that reads `human_answers` no longer sees a *stale* `_shared.md` line that is not in the live inbox
  (as in the brief_P0_shared fixture's second line) — the live inbox is treated as the truth.

## Roll back
`git revert <this commit>` on evolve/main; no data or state migration (memory/_shared.md files are plain text and are
regenerated by `sea.evolve.write_shared` each generation).

## For the human to decide

  `TASTE_MAX_*` in brief/task.py if you want a different balance.
- Whether rating comments should name the design id (the team cannot see other designs; kept because the id hints
  that it was a judgement on a whole design).
